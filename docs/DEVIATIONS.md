# Deviations from the reference implementation

Every intentional difference in behaviour between this port and upstream Steam Audio (`core/`) is recorded here.
Differences within a module's stated numerical tolerance (see `PORTING_PLAN.md` §5) are not deviations.

| Area | Upstream behaviour | Rust behaviour | Reason | Approved |
| --- | --- | --- | --- | --- |
| GPU backends | OpenCL, Radeon Rays, TrueAudioNext | Not implemented | Out of scope | yes (plan) |
| Vendor math libraries | IPP, MKL, vDSP, FFTS | Not used; `realfft`/`rustfft` and scalar/`std` SIMD | Out of scope; portability | yes (plan) |
| Embree ray tracer | Optional backend | Not implemented; built-in BVH tracer only | Out of scope | yes (plan) |
| Scalar type of math types | Templated on `T`; `float` and `double` typedefs | `f32` only | Only `float` is instantiated by the library; `double` variants are unused | yes (2.1) |
| `Vector<T,D> / Vector<T,D>` | Does not compile if instantiated (`lhs /= rhs` on a const reference); never used | Element-wise division by reciprocal multiplication | Upstream bug, unreachable | yes (2.1) |
| `SquareMatrix::transpose()` (in place) | Swaps every `(i,j)`/`(j,i)` pair twice, so it is a no-op; never called | Not ported; `transpose()` returns a copy (upstream `transposedCopy`) | Upstream bug, unreachable | yes (2.1) |
| Uninitialized matrices | Default constructor leaves elements uninitialized | Always initialized (`ZERO`) | Safety | yes (2.1) |
| `Box::coordinates(i)` | Pointer arithmetic over 16-byte-aligned members, unchecked index | `Aabb::bound(i)`, panics on `i > 1` | Safety | yes (2.1) |
| Out-of-range indices and shape/length mismatches in general | Unchecked: raw-pointer or `std::vector` access without bounds checks (undefined behaviour), e.g. `Vector::operator[]`, `HRTFMap`/`HRTFDatabase` HRIR and Ambisonics coefficient accessors, `DynamicMatrix` operations on mismatched shapes | Panics (Rust bounds checks and explicit `assert!`s); the rows in this table that name a specific case are instances of this rule | Safety; violated preconditions panic (see `CLAUDE.md`). The C API (stage 8) validates inputs first, see R7 | yes (review) |
| `leastSquares`, `leastSquaresL1` | Implemented only with Intel MKL; the default build throws `Status::Failure` | Not ported | Unused without MKL (out of scope) | yes (2.3) |
| `Array<T, N>` | Custom multi-dimensional array with pointer tables | `Vec<T>` and slices | Idiomatic Rust; no behaviour change | yes (2.3) |
| `Sampling` hemisphere docs | Comment says the hemisphere's normal is +y | Samples have `z <= 0` (normal −z) in both; only the doc comment is corrected | Upstream comment is wrong | yes (2.2) |
| `AudioBuffer` storage | `float* const*`: one pointer per channel, channels may live anywhere | One contiguous planar array (owned `Vec<f32>` or a borrowed slice view) | No `unsafe`, no pointer tables. Upstream only builds non-owning buffers over contiguous data internally; the C API (stage 8) copies user channel arrays into preallocated scratch | yes (2.4) |
| `convertAmbisonics` with FuMa above order 3 | Reads past the 16-entry index/gain tables (undefined behaviour) | Panics | Safety | yes (2.4) |
| `AudioBuffer::downmix` with 0 input channels | Reads `in[0]` (undefined behaviour) | Panics | Safety | yes (2.4) |
| FFT sizes below PFFFT's minimum | `FFT` throws `Status::Initialization` for real sizes < 32 and complex sizes < 16 (after rounding up to a power of two) | Every positive size works; size 0 panics | No reason to fail; upstream never relies on the exception | yes (2.5) |
| `FFT` domain | One class; the domain is a constructor argument and calling the wrong `apply*` overload is undefined | Two types, `RealFft` and `ComplexFft` | Type safety | yes (2.5) |
| `FFT::apply*` buffer sizes | Reads/writes exactly `numRealSamples`/`numComplexSamples` through raw pointers | Slices must have exactly those lengths, otherwise panics | Safety | yes (2.5) |
| `SphericalHarmonics::legendre(n, x)` for `n >= 4` | The general case calls `legendre(n, x)` with the same `n` and never terminates (stack overflow) | Bonnet's recurrence `P(n) = ((2n - 1) x P(n-1) - (n - 1) P(n-2)) / n`, in `f32` | Upstream bug; reachable from `AmbisonicsBinauralEffect` and `PathEffect` at order >= 4 | yes (2.6) |
| `sh::EvalSH` with `m` outside `[-l, l]` | The `CHECK`s are compiled out; the `switch` falls through into the next band's case (or returns 0) | Panics | Violated precondition | yes (2.6) |
| `sh::ProjectFunction`, `ProjectSparseSamples` | `ProjectFunction` seeds `std::mt19937` from `std::random_device` (not reproducible; the `double*` overload also clears only half the output); `ProjectSparseSamples` needs MKL | Not ported | Unused by the library | yes (2.6) |
| `SHRotation::setCoeff`, `getRotatedCoeff`, `apply(order)`; `sh::Rotation(order, other)`, `rotation()` | Stateful single-coefficient API; copy-extend constructor; `rotation()` always returns a zero quaternion | Not ported | Unused by the library | yes (2.6) |
| `IIR8`, `IIR8Filterer`; `IIR`/`IIRFilterer` order switching | `IIR` holds a biquad and an 8th-order cascade and `IIRFilterer` switches between them on `IIR::sUseOrder8` / `IIRFilterer::sEnableSwitching`, globals nothing sets | Not ported; `Iir`/`IirFilterer` are the biquad | Dead code; no globals in the core | yes (2.7) |
| `IIR2Filterer` block size | 4 or 8 samples per step, chosen from the global SIMD level when the filterer is constructed | Always 8 (upstream's AVX path, bit-exact) | Deterministic results on every platform; see R8 | yes (2.7) |
| `IIR2Filterer` default state | `mFilter` uninitialized; the buffer path outputs zeros, the single-sample path uses garbage | Zero coefficients: both paths output zeros | Safety | yes (2.7) |
| `IIR2Filterer::resetFilter` | Zeroes the block coefficients but keeps `mFilter`, so tail samples are still filtered; only called from the constructor | Not ported | Unused | yes (2.7) |
| `Allpass(delay, gain, frameSize)` constructor | Calls `reset()` after `resize()`, which zeroes the gain; never used (callers default-construct and `resize`) | `Allpass::new` keeps the gain, like `resize`; `reset()` still zeroes it | Upstream bug in unused code | yes (2.7) |
| `Delay::get`/`put` of more samples than the ring holds | Buffer overrun in the `n`-sample overloads (the `float4_t` ones wrap) | Wraps as often as needed; panics on an empty ring | Safety | yes (2.7) |
| Octave bands | 11 bands with `IPL_ENABLE_OCTAVE_BANDS` (off by default) | 3 bands only | Default build | yes (2.7) |
| Malformed `.hrtf` data | Read through raw pointers without bounds checks; no HRIRs divides by zero; a missing Ambisonics sampling rate reads past the end | `Error::MalformedHrtfData` | Safety | yes (3.1) |
| `HRTFDatabase::convertToMinimumPhase` | Computed (with a magnitude-phase decomposition) in `precomputeAmbisonicsHRTFs`, but the result is never used | Not ported | Dead computation; no observable effect | yes (3.1) |
| `HRTFDatabase::sEnableDCCorrectionForPhaseInterpolation`, `sEnableNyquistCorrectionForPhaseInterpolation` | Mutable globals, `false`, toggled only by an interactive test tool | Not ported (always off) | No globals in the core | yes (3.1) |
| `Loudness::sMaxVolumeNormGainDB` | Mutable global (12 dB) that nothing changes | Constant `MAX_VOLUME_NORM_GAIN_DB` | No globals in the core | yes (3.1) |
| `HRTFDatabase::saveAmbisonicsHRIRs(FILE*)` | Writes Ambisonics HRIRs for the `hrtf2sh` tool | Not ported | Tool-only | yes (3.1) |
| `FFT::applyForward` (real) Nyquist bin | Imaginary part is stale: that of the last spectrum passed to `applyInverse` on the same object (R11) | Always 0 | Upstream bug; never non-zero in upstream's own pipelines | yes (3.2) |
| `OverlapSaveConvolutionEffect::numTailSamplesRemaining` | Goes negative (−frame size per extra call) when `tail` is called after the tail has ended | `num_tail_samples_remaining()` returns `usize`, clamped at 0; the internal counter and returned states match upstream | Idiomatic unsigned count; same meaning for callers | yes (3.2) |
| Passing a new overlap-save IR | `TripleBuffer<OverlapSaveFIR>*` (swapped with the effect's IR on `updateReadBuffer`) or a `const OverlapSaveFIR*` cast to non-const and swapped, plus an `fftIRUpdated` flag | `Option<&mut OverlapSaveFir>`: `Some` means updated; the caller's FIR receives the previous IR | No hidden mutation through `const`; the triple buffer belongs to simulation (stage 6) | yes (3.2) |
| Unused convolution parameters | `numSamples` in the overlap-save params, `irSize` in the mixer settings | Dropped from `apply`; the mixer ignores `ir_size` | Never read upstream | yes (3.2) |
| `SpeakerLayout` storage | Non-owning `const Vector3f*` (the caller keeps custom speaker arrays alive); `SpeakerLayout(Custom)` gives 0 speakers and a null pointer | Owns a `Vec<Vector3>`; `SpeakerLayout::new(Custom)` panics (use `custom(vec)`) | No dangling pointers; a custom layout without speakers is a violated precondition | yes (3.3) |
| `BinauralEffectParams::hrtf` | `const HRTFDatabase*`, cast to non-const inside `apply` | `&mut HrtfDatabase` | No hidden mutation through `const` | yes (3.3) |
| `BinauralEffect` with a mono input and spatial blend below 1 (nearest neighbour) | Computes the blended HRTF, then uses the stored one | Uses the stored HRTF without computing the blend | Dead computation; same output | yes (3.3) |
| `PanningEffect::secondOrderPanningWeight` | Declared and implemented, never called | Not ported | Dead code | yes (3.3) |
| Ambisonics effect settings and params | Structs of pointers: `speakerLayout`, `direction`, `orientation` and `hrtf`; a null `hrtf` in the decode settings or params disables binaural decoding | Constructor arguments; `AmbisonicsDecodeParams` holds the orientation by value and `hrtf: Option<&HrtfDatabase>`; the decode effect takes `Option<&HrtfDatabase>` | Idiomatic; no null pointers. Same behaviour | yes (3.4) |
| SOFA loading from a file name (`mysofa_load`) | Reads through `FILE*`: seeking past the end succeeds and positions are `long` | `Hrtf::load_file` reads the whole file and parses it like `mysofa_load_data` (in-memory: a seek past the end fails with `EINVAL`) | One code path, no `unsafe` I/O. Valid files load identically; a corrupt file may fail with another status code | yes (3.5a) |
| SOFA parser limits | Unbounded recursion on nested datatypes and self-referencing heap blocks (stack overflow), loops that never finish on attributes of empty elements repeated up to 2^64 times or on heaps re-read without end, chunked datasets of 2 GiB or more (an `int` size: crash or misread), inputs over 2 GiB | `Error::ResourceLimit` (code `MYSOFA_UNSUPPORTED_FORMAT`): datatype nesting over 32, indirect heap blocks nested over 32, attributes with over 2^20 elements (reported as `MYSOFA_INVALID_FORMAT`, like every attribute error), more than 16 × input + 1 MiB bytes consumed, chunked datasets of 2 GiB or more, inputs over `i32::MAX` bytes | SOFA files are untrusted input: the parser must terminate with an error. Real files are far from every limit | yes (3.5a) |
| SOFA chunk geometry that divides by zero or overflows (`INT_MIN / -1`) | Integer division trap (crash) | `Error::Internal` | Safety | yes (3.5a) |
| Object reference to an unnamed object | `strdup(NULL)` (crash); unreachable, as only the root group is unnamed and it is never resolvable in time | Empty name | Safety | yes (3.5a) |
| libmysofa's version 2 B-tree reader (`btreeRead`), `mysofa_tospherical`, `mysofa_loudness`, `mysofa_minphase`, `mysofa_interpolate`, the cache and `mysofa_getfilter_*` | Implemented | Not ported | Never called on Steam Audio's path (`mysofa_open_no_norm` + lookup and neighbourhood, which 3.5b ports) | yes (3.5a) |
